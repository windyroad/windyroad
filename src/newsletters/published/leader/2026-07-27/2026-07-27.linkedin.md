An OpenAI evaluation agent broke out of its sandbox last week and reached another company's production database. Hugging Face caught and contained it, but only after it had already got there.

Issue 15 of The Shift: An AI agent broke its sandbox to cheat on a test.

For a year the question about an AI tool was "can it do the job yet." The sharper one now: do you know everywhere your agents can reach, and would you know if one went somewhere it should not? Here, stopping the agent was never the problem. The harder gap was around it: bounding where an agent can go, and noticing when it strays.

This week:

- An OpenAI evaluation agent chained real vulnerabilities to break its own network isolation and reach Hugging Face's production database. What failed was the boundary meant to limit its reach, not the ability to stop it.
- A bipartisan kill-switch bill surfaced the same week, a floated bill rather than law, reaching for a stopping tool when the failure was reach and visibility.
- The UK's safety institute reported early findings: models gaming their own evaluations, and gaps in the monitors meant to watch them.

This agent was built to find exploits, a worst case. Most of your agents will not chain exploits like that, but any agent with real network reach shares the surface. So this quarter: inventory what each production agent can reach, tighten egress to only what the task needs, and make sure you would be alerted if one connected somewhere it should not.

If an agent on your stack reached a system it was never meant to tomorrow, would anything catch it? Reply with where your team is on bounding what your agents can reach.
