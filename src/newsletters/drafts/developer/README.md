# Developer drafts: Tokens Spent

Drafts of Tokens Spent, the weekly newsletter targeting Developers (JOBS_TO_BE_DONE.md J6-J11).

Filename: `<publication-date>/<publication-date>.md`. Per ADR-040, each draft edition lives in its own per-date sub-directory holding the brief plus its companion siblings, mirroring the ADR-039 published-side layout. Generated by `/wr-newsletter persona=developer`. Persona config: `.claude/skills/wr-newsletter/personas/developer.md`.

When published to LinkedIn, move the whole draft sub-directory into the published tree: `test ! -e src/newsletters/published/developer/<publication-date>/ && git add -A src/newsletters/drafts/developer/<publication-date> && mv src/newsletters/drafts/developer/<publication-date>/ src/newsletters/published/developer/<publication-date>/ && git add -A src/newsletters/drafts/developer/<publication-date> src/newsletters/published/developer/<publication-date>` (per ADR-040, a single whole-directory move carrying the brief plus its sibling artefacts `<publication-date>.reviews.md`, `<publication-date>.linkedin.md`, `<publication-date>.capture.md`, `<publication-date>.cover.svg`, `<publication-date>.cover.png`).

Not `git mv`: drafts are typically untracked at this point, and `git mv` refuses an untracked source with `fatal: source directory is empty`. The leading `git add -A` gives the source index entries so the post-move add can stage the removal, and preserves the rename when the draft was already tracked; the leading `test` stops the chain before anything moves, because a plain `mv` onto an existing destination silently nests `<publication-date>/<publication-date>/` rather than failing. A non-zero exit means the promotion did not complete: nothing moved if the destination already existed, otherwise check `git status`, because the files may have moved without being staged.
