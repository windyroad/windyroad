## Architect Decisions Compendium

> Split out of [`what-will-surprise-you.md`](what-will-surprise-you.md) on 2026-08-08 (Tier 3 budget rotation, split-by-subtopic: the file was over the 5120-byte ceiling and this entry is a self-contained sub-topic over 1 KB).

- **Do not run the full-file compendium generator, and expect to hand-fix em-dashes after every ADR edit.** `wr-architect-generate-decisions-compendium` self-reports `DEPRECATED per ADR-078` and is a bootstrap backstop only. Compendium authoring moved to the `architect-compendium-update-entry.sh` PostToolUse hook that fires on every ADR edit; running the generator after an edit clobbers the entry the hook already authored and staged, and re-introduces em-dashes wholesale (47 in one 2026-08-05 recovery). Recovery is `git checkout -- docs/decisions/README.md`, which restores the hook's staged version. The hook's own output still emits em-dashes, which the P025 no-em-dash Bash hook then blocks, so the working sequence is: edit the ADR, let the hook author the entry, grep the index for U+2014 and rewrite the hits to ASCII, then commit. Tracked as P087. Trimmed on 2026-08-29 from three stacked dated updates down to the advice that is still live; the superseded 2026-06-27 `RISK_BYPASS: architect-compendium-deferred` recipe is in git history.

- **Any write to a decision file, including a frontmatter-only one, can silently destroy a hand annotation in the compendium.** `architect-compendium-update-entry.sh` gates on the path `docs/decisions/<NNN>-*.md` and does not distinguish a frontmatter edit from a body edit. It does not patch the entry: it spawns a `claude -p` call told to re-author that entry **from the record's current body**, passing the existing entry as context with no instruction to preserve anything. Its fail-closed guard compares only the set of ADR ids and the count of `## ` headings, so it is blind to content changes inside the entry it just rewrote, and on success it runs `git add docs/decisions/README.md` itself, so a lost annotation is staged rather than left visible in `git status`. Diffing `docs/decisions/README.md` before committing is the only control that exists. This matters most where a compendium entry carries a dated staleness note that its record's body does not: the ADR-027 entry is the single `< 5` in the compendium and is safe only because of that note, while ADR-027's body still carries bare `(< 5)` twice. **Re-verified against wr-architect 0.21.4 on 2026-08-29**, where all of that still holds. Two things the first reading missed. The hook self-declares an opt-out in its own header, `ARCHITECT_AUTO_UPDATE_COMPENDIUM=0`, which suppresses it entirely; that trades the annotation hazard for a stale compendium that `architect-readme-pairing-check.sh` then flags at commit, so it is a second control rather than a way out, and you still diff the file before committing. And 0.21.4 **does** recompute the derived counts, rewriting `**Total ADRs:**` and both section preambles; older notes claiming it never touches them are stale.
