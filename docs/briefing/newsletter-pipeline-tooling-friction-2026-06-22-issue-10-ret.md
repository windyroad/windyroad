## Newsletter pipeline + tooling friction (2026-06-22 Issue 10 retro)

- **Any body edit AFTER the gate sequence (or post-finalise) must re-run the FULL gate set, not just voice + lint (P099).** During Issue 10's post-finalise editing (apocryphal-anecdote fix, human-code-review reframe, CTA swap, external-review fixes, "the brief" to "we" fix), the agent kept voice + structural-lint current after each edit but did NOT re-run critic / editor / cog-a11y / content-risk. Tom caught it ("have the cog-a11y and strengths/weaknesses checks been run?"). Re-running them surfaced real new weaknesses (Item 2 missing metric, Item 4 urgency contradiction, Item 3 abstract heading, LinkedIn Gemma-frontier-grade contradiction). Rule until P099 lands a SKILL fix: after ANY post-save/post-finalise edit to the brief or LinkedIn body, re-run voice + content-risk + newsletter-critic + editor + cog-a11y + cross-edition + structural lint, not the cheap subset.
- **Two silent newsletter format traps, caught only by eye / by Tom (P100).** (a) `/wr-newsletter-cover` clips hook line 2 at ~44 chars (60px) with no overflow warning; trimming the predicate to fit produced a dangling fragment that reads as truncated ("Governance, trust and new skills" looked cut off). Keep cover hook line 2 a COMPLETE phrase under ~40 chars and eyeball the render. (b) `scripts/check-newsletter-structure.sh` model-name check (f) false-positives when a model name is sentence-final ("Gemma 4." with the period captured into the token) vs the brief's "Gemma 4"; fired on the cover reword and twice on LinkedIn. Workaround: never end a sentence on a model name (move it mid-sentence, space/comma after).
- **Google News RSS article links use opaque tokens; diagnose before dropping a citation (extends P010/P014/P091; memory feedback_diagnose_url_failure_before_dropping).** `news.google.com/rss/articles/CBMi...AU_yqL...` tokens need Google's server-side batchexecute to decode; a plain GET / browser-open returns the Google News shell (looks "invalid"), and a WebFetch summarisation of the feed can mis-relay the token. When a link will not resolve: `curl` the RAW RSS XML (not WebFetch) to confirm the story + see corroboration breadth, then recover the canonical publisher URL via a search whose results expose real hrefs (WebFetch on the DuckDuckGo HTML results page worked). Reuters/WSJ/Politico 401/403 on direct fetch = bot-block (page exists), not 404. Do NOT drop a corroborated citation on a resolution failure; diagnose first.
- **The pipeline keeps recommending human code review and generic rotation CTAs, against Tom's stance (P101; memory feedback_humans_ratify_decisions_not_review_code).** Item copy, the `ai-landscape.md` Risk/Decisions vocabulary ("review-and-oversight load", "review pipeline"), and the three-lens action vocabulary default to "human review" as the answer to AI-generated code. Tom's position: humans ratify architecture + product-direction decisions (off the critical path); automated gates/evals carry code-level quality at AI pace; human code review gates delivery to human pace. Issue 06 ("More review will not fix AI slop") already argued this; later editions drifted. Separately, the persona's fixed rotating-CTA list produces weak generic CTAs ("Reply with what is breaking on your stack this quarter"); Tom wants edition-tied conversation CTAs.
- **The review gates fact-check URLs, not unsourced analogies / stated-as-history claims (P102).** Issue 10's opener stated an apocryphal "students can't write on slate" anecdote as historical fact; it passed voice, content-risk, critic, editor, cog-a11y, and URL-verify (which checks links only), caught only when Tom asked for a source. Stated-as-history claims and vivid analogies that carry no URL have no gate. Also: "apocryphal" was too obscure for the leader register (cog-a11y did not flag it; Tom did, preferring "probably made up"), and "the brief has tracked" leaked internal nomenclature into reader-facing copy (use team voice "we have tracked").
