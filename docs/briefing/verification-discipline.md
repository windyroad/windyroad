## Verification discipline

Checks that are wrong in the same direction as the work they check. This file exists because 2026-08-09 to 2026-08-10 produced five instances in one session, and the failure mode is not carelessness: each check was written immediately after the thing it verified, by the same reasoning, so it inherited the same assumption.
- **`wr-itil-reconcile-readme` exiting 0 does not mean the problems README is accurate.** On 2026-08-23, immediately after `git mv`-ing a ticket from `open/` to `known-error/`, the preflight returned exit 0 (clean) while the README's row for that ticket still read `Open`. The script reconciles the *inventory* (which IDs appear in which section) and does not read the Status column inside a row, so a status that moved without its row being rewritten is invisible to it. The P062 refresh-on-transition contract is what actually owns that edit, and it is the agent's job, not the script's. Treat the green exit as "no tickets are missing", never as "the README is right", and read the row you just changed.
- **Gates report the instances they notice; they do not enumerate.** On 2026-08-24 one defect class fired nine times inside a single newsletter edition, three more inside the ticket documenting it, and once in a ticket about something else: a claim corrected at the site a reviewer pointed at, left standing at its siblings. Six of those were introduced BY a fix. Every gate that caught one caught an instance. The proof is occurrence four, where the skeptic condemned a phrase at one site and explicitly cleared a sibling four lines below it in the same pass. A grep sweep afterwards found that sibling, then missed a fifth in the opener because the distinguishing word was the publication's own name and the real hit drowned in the masthead. What actually closes the class is an enumeration, not a search: list every sentence whose subject is the thing and whose predicate is the claim, then check each one. Run against that edition it produced thirteen candidates, eleven real, and ended a four-round streak in one pass. The general form: **a correction has as many sites as the claim has, not as many as the person has looked at**, and the person's count of remaining sites is itself unreliable. Ticketed as P162 with nine recorded occurrences, three of them inside the ticket.

- **Your own count is not evidence, and a passing test can be false assurance about the thing you are using it to prove.** Two shapes, one session. A reported motif count of two was three on disk, because the previous round had removed one instance and added another back; an external reviewer caught it by counting. Separately, `scripts/decisions-supersession.test.mjs` passing 8 of 8 was offered as proof a decision graph was complete, when that test only verifies relationships that have been DECLARED: an undeclared `amends` is invisible to it, and there was one. Then, fixing that, an `amended-by` key was added to a record that already had one, creating a duplicate YAML key that silently dropped a relationship. The test caught that. Derive every count from the file in the same turn you state it, and before citing a green test, check what it actually asserts. A third shape, 2026-08-29: the source may not state the thing you are reading off it. A reviews file said a loop was "run after every round", which is when it ran, not how many rounds it ran inside each pass; a verification note read the second off the first. Two sibling miscounts rode along in the same prose. Ask what the source states before quoting it for what you need.

- **A ticket's close criterion can be quietly superseded by a decision ratified after it was written.** P120's criterion, written 2026-08-05, said the fix is not working "if the loop runs more than one round per body pass". ADR-052, ratified five days later, made every newsletter reviewer gate blocking, so a surviving finding now holds the edition and each fix starts a further body pass. A verification note read a 24-round finalise against that criterion, called it a regression by a factor of twenty-four, and the ticket was flipped back to Known Error on Tom's confirmation of that reading. The twenty-four counted body passes; the criterion caps rounds inside one. Check what has been ratified since a criterion was written, and that the evidence counts what the criterion counts. Corrected on P120 and P113.
