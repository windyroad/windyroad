## How a decision is changed

Split out of `governance-surface-conflicts.md` on 2026-08-23 when that file went over the Tier 3 budget. This topic will grow as ADR-054 is applied, so it gets its own file rather than crowding the conflicts topic.

- **A decision is now changed by a new decision, never by editing the old one, and the rule is ratified.** `docs/decisions/054-a-decision-is-changed-by-a-new-decision-never-by-editing-the-old-one.proposed.md`, recorded 2026-08-16, ends the practice of appending an `## Amendment` section or a dated pointer to an overtaken record. Only frontmatter may change: `amends:`/`amended-by:` when part of a record is overtaken, `supersedes:`/`superseded-by:` when the whole record is retired, and the amending record must name the specific clause rather than just the record. `scripts/decisions-supersession.test.mjs` enforces both pairs in **both** directions, so a forward claim without its reciprocal goes red and so does a lone reciprocal. There is no green half: the claim and its reciprocal land in one commit or not at all. Six records carrying pre-existing `## Amendment` sections are grandfathered by a hard-coded allowlist in that test; dated-pointer blockquotes (ADR-007, ADR-008, ADR-027) are not in it and are neither caught nor protected. **Tom ratified the record on 2026-08-23** (`human-oversight: confirmed`), so work that applies it is no longer blocked; anything you read that calls it unratified predates that date. Applied for the first time on 2026-08-24, and three things only show up in use. The test's green is narrower than it looks: it verifies DECLARED relationships, so an undeclared `amends` passes unnoticed, and citing the pass as proof a graph is complete is false assurance. Adding a reciprocal to a record that already has one produces a duplicate YAML key rather than a merged list, which silently drops a relationship; the test does catch that. And landing a record unratified is the cheap direction, not the risky one, because refusal costs a `git rm` and two reverted frontmatter lines only while none of its enforcement surfaces have landed. A consequence that only shows up when you close a ticket, 2026-08-30: moving a ticket file between state directories kills every inbound ADR path reference to it, and ADR-054 forbids repairing them, because a path sits in the body. The architect returns ISSUES FOUND if you try, and it is right to. This is not a backlog to drain -- dead ticket paths already sit in ratified bodies, four of them inside ADR-020 alone (lines 19, 112, 136 and 164, one still using the flat filename-suffix scheme upstream ADR-031 (Problem-ticket directory layout) retired; local ADR-031 is an unrelated decision about Google News redirect resolution), and nothing lints them. Leave them; the record's own Neutral consequence already says an overtaken record keeps prose that is wrong read in isolation. The same prohibition covers drifted line-number anchors.
