# Project Briefing

Migrated from legacy `docs/BRIEFING.md` via `/wr-retrospective:migrate-briefing` on 2026-08-07.

## Critical Points (Session-Start Surface)

- **The risk scorer is a design reviewer, not a formality.** Its STOPs have repeatedly caught genuine design defects that architect passes missed. Read a STOP as a finding, not a gate to satisfy. When its remediations would each breach a decision, look for a third close rather than choosing between them. Related standing constraint: do NOT populate `docs/risks/` to clear the empty-register nudge. The queued slugs are sentence-shaped and the catalog filter matches on any single token, so 71 of 72 matched one ordinary commit; draining would destroy the hit-rate signal rather than restore it. ADR-056 holds the admission rule. ([risk-scorer-behaviour.md](./risk-scorer-behaviour.md), and the worked case in [risk-scorer-behaviour-archive.md](./risk-scorer-behaviour-archive.md))
- **Verify a ticket's own premises before acting on them, not just its prose.** Tickets carry stale claims about repo state (a governance tier said not to exist, a path pinned at a version no longer on disk). Read the file from disk. The same applies to ADR/RFC references in subagent verdicts. ([what-you-need-to-know.md](./what-you-need-to-know.md))
- **The maintainer persona is ratified as of 2026-08-09, and that unblocked executable internal-tooling work.** `docs/jtbd/internal-maintainer/` plus JTBD-400/401/402 all carry `human-oversight: confirmed`, `oversight-date: 2026-08-09`. While they were unconfirmed the JTBD edit gate withheld its marker on ISSUES FOUND, and "reasons from an unratified persona" was one an agent could not clear, so the whole class was unreachable AFK. Anchor tickets to these jobs in prose under `## Related`, never in header lines, and drop the provisional caveat. Tickets written before 2026-08-09 still carry that caveat; it is stale, not current state. ([what-you-need-to-know-archive.md](./what-you-need-to-know-archive.md), [governance-iteration-friction-2026-08-09-p115-iter.md](./governance-iteration-friction-2026-08-09-p115-iter.md))
- **A bare ID of any kind is ambiguous, and Tom cannot resolve one.** `ADR-NNN` collides across this repo and upstream `agent-plugins` (both number from 001; 014, 024, 028, 032 and 036 each hit an unrelated real decision). The same holds for problem numbers, and Tom named it directly on 2026-08-09: *"you need to remember that I have many projects all with their own problem numbers"*. Never let an ID carry meaning in a reply: name the thing, every mention, including the second and third in one conversation. The citation reads plausibly and points at a document that exists, so the error is quiet. Write `upstream ADR-NNN` for cross-repo references, and prefer grounding a claim in the artefact on disk over the number. ([governance-iteration-friction-archive.md](./governance-iteration-friction-archive.md))
- **The retro's own detectors are half-fixed upstream, and `command -v` answers presence-by-name, never which version ran.** As of 2026-08-29, `wr-retrospective-check-briefing-budgets`, `-check-ask-hygiene` and `-check-tickets-deferred-cause` all resolve and exit 0 here (shipped 0.27.1 per the changelog; they first appear in a cached `bin/` at 0.27.3 only because 0.27.1 and 0.27.2 were never cached). `wr-retrospective-check-readme-jtbd-currency` still exits **2** with `packages dir not found` when called bare and exits 0 silently when handed a directory. That remainder is P130, now parked and reported upstream as agent-plugins#453 together with the `analyze-context` Step 0 guard. `command -v` prints 0.27.5 for the three new names and 0.27.0 for the older ones, because several version `bin/` dirs sit on PATH and the first match per name wins; but every ADR-080 shim ends `exec "$CACHE_PARENT/$HIGHEST/scripts/<name>.sh"`, so the 0.27.0 shim runs the 0.27.5 script. The printed path locates the shim, not the code. Read the wrapper or trace the exec if you need the running version, and treat these notes as true-at-a-version. ([what-you-need-to-know.md](./what-you-need-to-know.md))
- **The architect can take several rounds, and the later rounds are the valuable ones.** Treat an ISSUES FOUND as the review working, not as a formatting problem to route around; the P126 fix went ISSUES FOUND four times before passing, and on 2026-08-29 a documentation-only P120 change went ISSUES FOUND three times, each round catching a different real defect in the reasoning rather than in the writing. ([what-will-surprise-you-archive.md](./what-will-surprise-you-archive.md)) The convergence case is separate and stronger: when two or three reviewers independently find the same thing, it is real. On 2026-08-09 the architect and the JTBD reviewer rejected the same defect in a first draft; on 2026-08-23 the architect, JTBD and voice reviewers each found the same over-broad predicate in the P154 lint. Convergence does not always mean the artefact is the wrong shape, but it always means the finding stands. ([governance-iteration-friction-2026-08-09-p109-iter.md](./governance-iteration-friction-2026-08-09-p109-iter.md))
- **A genuine PASS can still leave the edit blocked at any of six gates, and the cause is never the verdict string.** Confirmed against the installed hooks on 2026-08-09 (P124). Every governance marker is written by a `PostToolUse` hook matching the literal string `Agent`: architect, jtbd, risk-score, voice-tone, external-comms, style-guide. Neither a `SendMessage` resume nor a background-launched reviewer fires any of them, so dispatch a FRESH, SYNCHRONOUS `Agent` spawn. On `wr-architect` 0.20.0, which is what this repo runs, the mark hook routes an unparseable verdict into the same allow-with-marker branch as PASS, so asking for the literal `**Architecture Review: PASS**` is belt-and-braces rather than load-bearing, and a "no marker found" block after a genuine PASS means the marker landed under a session ID the gate does not read (P088). Only wr-architect names the resume trap, in one deny string; external-comms names the background half only; the remaining four gates block with no dispatch-shape hint at all. The six-way uniformity holds at the versions this repo pins and is already breaking upstream, so re-verify before relying on it. ([what-will-surprise-you-archive.md](./what-will-surprise-you-archive.md), [governance-iteration-friction-archive.md](./governance-iteration-friction-archive.md))
- **A `--body-file` call cannot clear the external-comms gate by reviewing the body: review nothing instead.** The gate scrapes the draft from the command string and finds none, so it hashes an EMPTY draft while the reviewer hashes your `<draft>` block; the keys never meet and it re-blocks after a genuine PASS. Keep `--body-file` and dispatch each reviewer with an empty `<draft></draft>` plus a pointer to the file. The risk reviewer has no Bash and cannot hash, so hand it `printf '%s\n%s' "" "<surface>" | shasum -a 256`; the voice-tone reviewer derives its key from the prompt, so it needs the same `SURFACE:` line and empty block. Both must be synchronous. Archived from 2026-08-08 and re-hit on 2026-08-29 for three wasted dispatches. ([what-will-surprise-you.md](./what-will-surprise-you.md))
- **Ask the risk scorer to verify an artefact's own claims against disk, not just to score it.** One sentence in the prompt; it has caught wrong shim counts, self-contradicting figures, and two false premises it was handed. ([governance-iteration-friction-archive.md](./governance-iteration-friction-archive.md))
