## Newsletter pipeline: why external review is still needed (2026-08-04 Issue 16 retro)

- **Do not add another newsletter gate before P120 lands.** Six gates already run. The Issue 16 evidence is that detection is not the bottleneck: the editor and skeptic gates DETECTED the defects and the pipeline handed them to Tom. Any new gate built while findings still route to Tom adds a surface to his review load rather than reducing it. P121 (prior-edition shape comparison) records this sequencing constraint explicitly in its Investigation Task 4.
- **Read the PRIOR EDITION's published artefacts before drafting, not just the skill template.** Recurring conventions live only in the corpus. Issue 15's LinkedIn post is 1,655 chars and carries an issue line ("Issue 15 of The Shift: ..."), the label "This week:", and a closing reply instruction. Issue 16's draft had none of the three and reached 2,993 chars, hitting LinkedIn's 3,000 ceiling three times; each time space was bought by cutting something load-bearing, and one of those cuts came back two rounds later as a reviewer finding. The template encodes the shape in the abstract; the last edition encodes what it actually looks like.
- **The LinkedIn companion is a teaser, not a compressed article.** The failure mode is packing the brief's argument into the post. Tom's correction: "the post is too long. The guts are in the article." Cutting the Martin/Booch/compilers passage to a single pointer sentence took it from 2,993 to 2,364 chars and made room for the four elements that were missing.
- **A regression test that passes against the buggy code proves nothing, and this is easy to get wrong.** The first P119 test passed pre-fix. Two fixture defects: padding under the 64KB pipe buffer (so SIGPIPE could never fire) and padding placed BEFORE the matched heading (so little was left unwritten when grep exited). Always run the falsification in BOTH directions: revert the fix, confirm the test fails, restore, confirm it passes.
- **Verify your own claims to the gates, not just subagent claims.** P082/P103 discipline applies inward. This session I told the risk scorer a commit "fixes two phantom ADR cross-references" when those edits had been blocked by the architect gate and never landed; the scorer caught it. Carrying intent forward as fact is the same failure class as propagating an unverified subagent citation.
- **The architect edit-gate can deadlock on `docs/decisions/`.** Findings on an ADR cannot be fixed because the gate blocks editing that file until it returns PASS, and it will not PASS while the findings stand. `docs/decisions/032-...proposed.md` is currently sitting with three phantom ADR references (ADR-066, ADR-068, a mis-numbered ADR-031), an invalid `4b.` list marker that renders as part of element 4, and an Amendment block quoting the Issue 16 disclosure in a person the final text contradicts. Not yet ticketed.
- **The `docs/decisions/README.md` compendium regenerates itself with em-dashes that violate this repo's own `no-em-dash-bash.sh` hook.** When that happens the hook fires on EVERY subsequent Bash call until the file is reverted or fixed. Known error P087 upstream. Revert it (`git restore --staged --worktree docs/decisions/README.md`) rather than fighting it; the ADR body is the authoritative surface and the compendium is a derived view.
