- **One of run-retro's own detectors cannot run here, and as of 2026-08-23 it declines silently rather than loudly.** `wr-retrospective-check-readme-jtbd-currency` produces no findings here, because there is no `packages/` tree in a consumer repo. That is P130, it is not your setup, and the honest answer here is "nothing to check". How it declines depends on how you call it, which is what earlier notes here missed. Invoked bare it prints `check-readme-jtbd-currency: packages dir not found: packages` on stderr and exits **2**; invoked with the project directory as its argument it exits **0** with no output at all, not even the `TOTAL packages=<N>` line its contract describes. Both were observed minutes apart on 2026-08-23 at the same shim version, so the entry that read this as the detector having gone quiet over time was wrong. Two things follow. The silent form is indistinguishable from a clean run, so pass the argument only if you want that. And the SKILL says this detector always exits 0, which the bare form does not, so an orchestrator that trusts the exit code gets a false failure. The Tier-3 budget pass has now gone missing again, and the round trip is the lesson. `wr-retrospective-check-briefing-budgets` was confirmed working on 2026-08-23; on 2026-08-25 `command -v` could not find it, along with `wr-retrospective-check-ask-hygiene` and `wr-retrospective-check-tickets-deferred-cause`. Nothing was uninstalled: five versions sit in the cache (0.18.1, 0.25.0, 0.27.0, 0.27.3, 0.27.4), 0.27.4 ships all three shims, and PATH resolves to 0.27.0, which ships none of them. So an earlier note was falsified by an upgrade and this one by a rollback, with nothing local to notice either time. Two things follow. Resolve the shim before trusting a presence claim: `command -v <shim>` prints the versioned path, and comparing it against `ls ~/.claude/plugins/cache/windyroad/<plugin>/*/bin/` tells you whether the gap is a missing feature or a stale PATH. And treat every note in this file about which detectors exist as true-at-a-version rather than true, including this one. `wr-retrospective-check-autocreate-rfc-scope`, `wr-retrospective-check-readme-jtbd-currency` and `wr-retrospective-measure-context-budget` all resolve at 0.27.0 and work.

- **When your own measurement argues against something the evidence names, suspect the measurement first.** On 2026-08-23 the P154 iteration nearly dropped a check the witness explicitly named as recurring, because a measurement said it would fire 43 times across the published archive. The measurement was mine and it was broken: the predicate tested for a list marker at column 1, so every indented list item counted as prose. Corrected, the same check fired zero times and shipped. The JTBD reviewer is what forced the re-look, on the grounds that the ledger recorded that defect twice while the check being kept in its place had never fired at all. This is the verify-before-asserting family (P032, P045, P082, P103) reaching a surface those tickets do not name: not a ticket's prose, not an upstream placement claim, not a subagent's artefact reference, but a number you produced yourself thirty seconds ago. A self-produced measurement feels like evidence in a way a citation does not, which is exactly what makes it hard to doubt. The tell is cheap: a measurement that contradicts a recorded witness is a hypothesis about the measurement, so print the hits and read a few before believing the count.
