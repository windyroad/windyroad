- **The retro's own detectors are half-fixed upstream, and `command -v` answers a narrower question than it looks like it does.** Checked 2026-08-29 against six cached versions of `wr-retrospective` (0.18.1, 0.25.0, 0.27.0, 0.27.3, 0.27.4, 0.27.5). Three detectors that were missing are now present and were run here, each exiting 0: `wr-retrospective-check-briefing-budgets`, `wr-retrospective-check-ask-hygiene` and `wr-retrospective-check-tickets-deferred-cause`, shipped in **0.27.1** per the plugin's own changelog (they first appear in a cached `bin/` at 0.27.3 only because 0.27.1 and 0.27.2 were never cached here, which is exactly the trap of dating a feature from the cache). One detector is unchanged: `wr-retrospective-check-readme-jtbd-currency` still exits **2** with `packages dir not found: packages` when called bare, and exits 0 with no output at all when handed a directory. That remainder is P130, now parked and reported upstream as agent-plugins#453 along with the `analyze-context` Step 0 guard, which still tests a repo-relative path that cannot exist here. The part worth internalising is what `command -v` does and does not tell you. It prints 0.27.5 for the three new names and 0.27.0 for the older ones, because several version `bin/` directories sit on PATH and the first match per name wins. That is a fact about where the shim file lives, not about which code runs: every ADR-080 shim ends `exec "$CACHE_PARENT/$HIGHEST/scripts/<name>.sh"`, so the 0.27.0 shim executes the **0.27.5** script, confirmed here with `bash -x`. So `command -v` answers presence-by-name and never answers which version ran; if you need the running version, read the wrapper or trace the exec. Treat every note here about which detectors exist as true-at-a-version, this one included.

- **When your own measurement argues against something the evidence names, suspect the measurement first.** On 2026-08-23 the P154 iteration nearly dropped a check the witness explicitly named as recurring, because a measurement said it would fire 43 times across the published archive. The measurement was mine and it was broken: the predicate tested for a list marker at column 1, so every indented list item counted as prose. Corrected, the same check fired zero times and shipped. The JTBD reviewer is what forced the re-look, on the grounds that the ledger recorded that defect twice while the check being kept in its place had never fired at all. This is the verify-before-asserting family (P032, P045, P082, P103) reaching a surface those tickets do not name: not a ticket's prose, not an upstream placement claim, not a subagent's artefact reference, but a number you produced yourself thirty seconds ago. A self-produced measurement feels like evidence in a way a citation does not, which is exactly what makes it hard to doubt. The tell is cheap: a measurement that contradicts a recorded witness is a hypothesis about the measurement, so print the hits and read a few before believing the count.
