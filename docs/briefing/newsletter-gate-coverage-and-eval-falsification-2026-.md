## Newsletter gate coverage + eval falsification (2026-08-23 P152 iter)

- **When a gate's authority already exists and only its ROUTING was broken, a fixture aimed at the owning gate proves nothing (P152).** P152 read as "cognitive accessibility cannot catch an unparseable sentence". On disk it already could: ADR-052's implementation had rewritten step 15.4's prompt to say "your blocking authority is over comprehension", and two fixtures built to check that the gate catches the witness sentence both went GREEN under falsification against the pre-change skill. They were deleted rather than shipped. The real defect was one layer up: the editor, the critic and the critic rubric were each told to DROP anything resembling readability and named no destination, so nothing ever reached the gate that could act. The fixture that discriminates points at the gate that was DROPPING the finding, not the gate that owns it. Ask "which agent's instruction actually flipped?" before writing the prompt.
- **Prescribing a cross-gate hand-off is not enough; the receiving agent's output contract has to have a field for it.** The first version of the P152 fix told the editor to "name it and hand it over". ADR-020 closes the editor's axis vocabulary and its Step 6 forbids any output outside the fixed `EDITOR_REVIEW` block, so there was no field the finding could travel in: it would have become an ordinary editor blocker the drafter fixed inline, which is self-certification on an axis no gate had scored. The risk scorer caught this, not the architect. When adding cross-gate routing, check the destination's output block for a carrier before writing the instruction, and prefer an existing field (`axis: other` plus a marker prefix; the critic's verdict-free `RELEVANT CONTEXT` block) over a new one, which would need the format-fixing ADR amended.
- **`promptfoo@0.120.19` has three silent misconfiguration modes that read as results, not as errors (ticketed).** (a) Config-level `repeat: 3` is INERT: two fixtures produced two results, not six. `falsify.sh`'s comment and the sibling ADR-052 config both assume it works, so their "test instances" counts are really fixture counts. `--repeat 3` on the command line is the working form. (b) A provider's `config.env` block is NOT applied to `exec:` providers; the variable arrives unset and every fixture ERRORS. Pass values as provider-id arguments instead (`exec:bash ./run-agent-eval.sh <path>`), which promptfoo places before the rendered prompt. (c) Omitting `defaultTest.options.provider` silently falls back to a default grader (Vertex AI here, unconfigured) and reports the tests as **FAIL**, not ERROR, so a missing grader block reads as a genuine red result. Check the grading reason with `--output <file>.json` before believing any failure.
- **`falsify.sh` is generic and now parameterised; use it for agent files, not just SKILL.md.** `CONFIG`, `SKILL_PATH` and `BASELINE_REF` are all env-overridable, so pointing it at `.claude/agents/<agent>.md` with a pre-change ref falsifies an agent-prose fixture the same way. Its guard is `git diff --quiet -- "$SKILL_PATH"`, which compares the worktree against the INDEX, so a staged change passes it and the `restore()` trap puts back the staged content: staging is enough, committing is not required. To falsify a file that is neither staged nor committed, back it up, `git show <ref>:<path>` over it, run the eval, and restore by hand.
