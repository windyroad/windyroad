- **Risk scorer's release-layer doesn't auto-verify whether changeset commits are pushed.** It reads `.changeset/*.md` content and treats it as forward-looking "would deploy" risk. If the underlying feat/fix commits are already on origin/master (e.g. waiting for the changesets-action release PR to merge), the scorer will inflate release risk and trip ADR-042's above-appetite branch incorrectly. Workaround: supply commit-state context manually (use `git log --diff-filter=A` to identify the introducing commit, then `git merge-base --is-ancestor <commit> origin/master`) and override the score. Tracked as P046.

- **`scripts/push-watch.sh` auto-resolve used to commit a desynced manifest pair; fixed 2026-08-08, and the shape of the fix is worth knowing.** `dry-aged-deps --update --yes` rewrites `package.json` only, and push-watch used to commit both manifests with no install between, so `npm ci` rejected the commit with EUSAGE. It now runs `npm install --package-lock-only` to complete its own write, and routes the result through `manifest_refresh_route`. Three properties to rely on: it acts ONLY when both manifests were clean on entry (an operator-dirty manifest means it writes nothing, commits nothing and reverts nothing); it commits ONLY a pure spec-sync, where the lockfile delta is confined to the root `packages[""]` block, and hands anything that moves a resolved entry to `npm run fix:deps`; and it adds no halt of its own, so the existing stale-deps gate still does the routing. The scans live in `scripts/lib/manifest-sync.sh` and are pure jq, so they are cheap to reuse. P126 / RFC-006.

- **A published edition's `.reviews.md` is a first-class evidence source.** Issue 16's recorded its own defect unprompted: "that ledger describes a text this edition no longer carries". Reading the reviews sibling of a recent edition is often faster and more honest than reasoning about what the pipeline did.

- **Date the evidence against the fix before calling it a regression.** The same admission in a reviews file means opposite things depending on which side of the fix commit it landed. Issue 16's un-regated-companion admission sits at `bbb6ca1` (2026-08-04); ADR-047's stale-verdict mechanism landed at `4f342a6` (2026-08-08). Pre-fix, so it raises P099's verification bar; post-fix it would have falsified the mechanism and re-opened the ticket. `git log --format=%ad -1 <file>` plus `git merge-base --is-ancestor <evidence-commit> <fix-commit>` settles it in one call, and the wrong answer routes an iteration into re-fixing something that already works.

- **A duplicate check can land on a ticket in `verifying`, and that is still a hang-off rather than a new ticket.** The P117 residue (editing continues after the gate battery terminates, so verdicts attach to superseded text) is P099's defect statement verbatim, and P099 already had a shipped fix awaiting verification. Minting a sibling would have split one defect across two tickets and hidden that the residue is exactly what P099's next verification must exercise. Search `docs/problems/` across ALL state directories, not just `open/` and `known-error/`.

- **Parking an upstream-blocked ticket is structural here, not a judgement call.** ADR-036 sets a three-condition predicate: the investigation names a specific fix site, that site lives under `~/.claude/plugins/cache/<vendor>/<plugin>/<version>/`, and this project carries no `packages/<plugin>/` source tree. When all three hold the ticket parks regardless of how high its WSJF is or whether a local workaround exists, and the ADR has already litigated the queue-honesty objection: leaving it ranked means the orchestrator re-selects work it cannot action every loop, which is P096. The park is a five-step workflow, not a rename: verify the bug on the LATEST cached version, search for an existing upstream issue, file one and record it under `## Reported Upstream` BEFORE the transition, add a `## Parked` section, then move the README row from WSJF Rankings to Parked in ID-sort position. Two things are easy to miss. Parked carries WSJF multiplier 0, so the ticket's own WSJF line must be recomputed as part of the transition. And 15 of this repo's 16 parks are now this same classification, which is ADR-036's own reassessment trigger.
