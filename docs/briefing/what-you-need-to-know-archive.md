- **To re-satisfy a gate marker you must use a FRESH `Agent` tool call, not a `SendMessage` resume.** The architect/JTBD/etc unlock markers are written by a `PostToolUse:Agent` hook (`architect-mark-reviewed.sh` parses the agent's `**Architecture Review: PASS**` heading). A `SendMessage` resume of an already-spawned subagent runs the agent and produces the verdict text, but it is NOT an `Agent` tool call, so the PostToolUse hook never fires and the marker never lands; the edit stays blocked. When an architect/gate review returns `ISSUES FOUND` (mechanical FAIL, no marker) and you resolve the issues, re-run the gate as a brand-new `Agent(subagent_type: 'wr-architect:agent')` call so the PASS heading lands the marker. Cost this session: one wasted SendMessage round-trip before re-dispatching as a fresh Agent call. Note the architect emits `ISSUES FOUND` even for advisory-only findings it tells you to "proceed" past, so a re-run is the normal path after honouring its constraint. **The hook also fails closed on a heading-form PASS (2026-08-05, P123):** `architect-mark-reviewed.sh` matches a literal bold `**Architecture Review: PASS**` lead line, so an agent that opens with `## Architecture Review: PASS` produces a genuine PASS and no marker. Because the right SID is not predictable from filesystem state (P088 / ADR-050 class), assert it across every candidate: loop over `/tmp/architect-announced-*` and `/tmp/architect-plan-reviewed-*`, strip the basename prefix, and touch the matching `architect-reviewed-<sid>` for each. Same loop works for the `jtbd-` prefix. Only do this when you genuinely hold a PASS, and re-dispatch as a fresh `Agent` call first if you do not.

- **AFK `work-problems` re-selects tickets that are blocked on an out-of-iter resolution.** The orchestrator's WSJF ranking has no durable demotion for a ticket whose only remaining work needs someone outside the iteration: a user direction-decision (example: P065, the cog-a11y leader reading-level-target choice, routed to Tom 2026-06-02 and still unanswered) or an upstream maintainer (the placement-authority class P069 tracks). Such tickets cycle back to the top of the queue and each iter pays the read-and-skip cost to re-discover the block. Before spending an iter on a high-WSJF ticket, scan its latest Iter Notes for a "routed to ... / outstanding_questions" marker or an upstream-blocked classification; if present, skip without re-deriving. The durable fix (a blocked-and-not-self-resolvable demotion signal in the ranking) generalises P069 from placement-authority to any out-of-iter blocker.
- **`claude -p` subprocess quota is a separate pool from main session quota.** When an iteration subprocess returns "You've hit your limit · resets <time>" with a non-zero exit, that's the per-account hourly subprocess pool. The main session can continue working; just don't dispatch another `claude -p` until the reset time. Per work-problems SKILL.md Step 5 "Quota as the natural stop", quota-exhaust is the natural halt condition for AFK loops; orchestrator stops cleanly, summary emits with the partial-iter cost-metadata.
