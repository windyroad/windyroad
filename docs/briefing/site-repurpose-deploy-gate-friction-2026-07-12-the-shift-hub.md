## Site repurpose + deploy-gate friction (2026-07-12 The Shift hub retro)

- **This is a Next.js static export (`output: 'export'` in next.config.mjs), so `next.config.mjs` `redirects()` DO NOT fire.** Deploy is Netlify. Route redirects (e.g. retiring pages) MUST go in `netlify.toml` `[[redirects]]` (status 301 permanent / 302 temporary), NOT next.config. The risk-scorer and I both initially assumed next.config; the pipeline scorer caught it. Existing working examples live in netlify.toml (`/ai-teams`, blog slug redirects).
- **`accessibility-lead` reviews MARKUP correctness (aria-hidden, roles, heading order, alt) but does NOT compute actual colour contrast against the built CSS. The CI axe gate does, and it will block the deploy.** This session accessibility-lead PASSED the new homepage, then CI failed: a `Button variant="ghost"` (white text, `#FFFFFF`) placed in a `.light` section rendered at 1.09:1. Ghost is a dark-section variant; on light use `variant="outline"` (accent `#B8390F` = 5.31:1). Rule: match Button variant to section background; do not put ghost/white-text controls in `.light` sections. The pipeline risk-scorer flagged this as a standing recurring trap.
- **The RISK-POLICY.md staleness commit-gate hardcodes 14 days and ignores the policy's own declared "quarterly" cadence, so once the policy ages past 14 days it blocks EVERY commit mid-session (P105).** Clearing it is an operator re-attestation via `/wr-risk-scorer:update-policy` (or `/risk-policy`). It is NOT fixed in risk-scorer 0.17.0. Do not fake-attest; genuinely re-review and bump the Last-reviewed date. The bug lives upstream in `@windyroad/risk-scorer`.
- **Dispatch `wr-risk-scorer:pipeline` and `wr-risk-scorer:policy` SYNCHRONOUSLY (`run_in_background: false`).** A background-launched scorer/validator does not fire its PostToolUse mark hook, so the commit-bypass / RISK-POLICY-edit marker never persists and the gate re-blocks despite a within-appetite PASS (P402). Bit me twice this session (commit gate, policy write gate).
- **The `wr-risk-scorer:update-policy` skill text mandates an ADR-042 bypass section that does NOT exist in this repo** (this repo's ADR-042 is an unrelated newsletter-gate decision; the skill means the plugin's own upstream one). Do not add it. **The band half of this entry is superseded as of 2026-08-09.** The skill's `3-5 Low` bands were adopted on Tom's direction as ADR-049, so they are now this repo's bands too, and the appetite reads `Threshold: 5 (Low)`. Authoritative: `1-2 Very Low, 3-5 Low, 6-9 Medium, 10-16 High, 17-25 Very High`, appetite **5 or below**, plus a local constraint upstream does not have: a residual of exactly 5 is admissible only at likelihood 1 with a **named** control. Always write `upstream ADR-086` for the cross-repo precedent. See memory `reference_update_policy_skill_phantom_adrs.md`.
- **`push:watch` refuses to push when the most recent CI run on master is red.** When your new commit IS the fix for that red run, the sanctioned override is `mkdir -p /tmp/wr-push-watch-no-session && touch /tmp/wr-push-watch-no-session/red-ci-acknowledged` (single-shot, deleted on use), then re-run `npm run push:watch`.
- **The OG share image regenerates automatically at `prebuild` (`scripts/generate-og-image.mjs`) from the `HERO_HEADLINE_*` / `HERO_SUBTITLE_*` constants in `src/lib/siteCopy.mjs`.** Editing those constants updates `public/img/og-image.png` on the next `npm run build`; no manual image work needed.
