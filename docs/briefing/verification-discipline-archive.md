Rotation is by signal, matching this tree's precedent: none of these three was exercised in that session. Nothing is deleted.

- **`git rev-parse <sha>^2` fails identically for a non-merge commit and for a commit not in your clone.** So a loop reporting "single-parent" may be reporting "absent". On 2026-08-10 that produced a confident wrong answer about seven publish commits, and those SHAs turned out to be unfetchable from the remote too, so no local check could ever settle it. `gh api repos/:owner/:repo/commits/<sha> --jq '.parents | length'` answers it without needing the object, and changed the finding from five-of-five to twelve-of-twelve. Reach for the API whenever a git question might be about presence rather than shape.
- **`git commit --amend --only -- <paths>` does not remove a path already in the commit.** It restricts what is taken *from the index*, not what stays in the commit. To drop a file, set its index entry to the parent's version (`git checkout HEAD~1 -- <path>`) and include it in the `--only` list, so the amended commit's content for that path matches its parent and git drops it. Costs a cycle to discover, because the amend appears to succeed.
- **The architect marker is invalidated by any substantive change under `docs/decisions/`, including your own.** Writing an ADR and then editing an unrelated file re-blocks the edit until the architect is re-dispatched. Hit three times in one session. Not a defect, but budget for it: land the ADR last, or expect a refresh round mid-task.

- **When a check and the work it checks share an author and a minute, they share their blind spot.** Five from one session. A rotation script and its assertion both assumed paragraph boundaries the file did not have, and it took a file from 7541 to 643 bytes before the restore. An em-dash assertion tripped on the word `retry-all-errors` inside my own explanatory comment. A link checker used `tr -d '(./)'`, which strips the dot in `.md`, so every link read as broken. An archive assertion demanded one signal-score marker per entry when historical entries never carried them. A merge-shape check conflated two different failures (below). The pattern is worth more than any individual instance: **write the check against the requirement, not against the implementation you just wrote.** Three of the five were caught only because the assertion fired before the write, which is the habit that saved them.
- **A hook regenerates `docs/decisions/README.md` on every ADR write, and it both emits em-dashes and leaves its own counts stale.** Three emissions in one session, one of them inside rendered body prose rather than a heading. The counts go stale on every single ADR, and there are two of them (the header total at line 14 and the section preamble at line 20); correcting only the first leaves the file self-contradicting. P087 and P135 respectively, deliberately separate tickets: one is about what the tool emits, the other about arithmetic it never does. Two further details from the 2026-08-23 P145 iteration. The regeneration re-fires on every ADR *edit*, not just the first write, and the generated sentence is reworded each time, so a replacement string that worked on the first pass silently misses on the second: match on surrounding words and re-scan after every edit. And the scanner cannot tell an illustration from prose, so a briefing entry that quotes the offending character blocks on itself.
- **A freeze is only a freeze if nothing edits under a running gate, including you acting on a different gate's result.** The digest-freeze discipline works, and it broke twice on 2026-08-24 for the same reason both times: one gate returned a blocking finding while another was still reading, and acting on the first moved the file under the second. The second gate then reviewed superseded text and its verdict could not be counted. Neither break was ignorance of the rule; both were the arrival of a result that felt urgent. The fix is to queue: collect findings from every gate in flight, apply them in one pass, re-freeze, re-dispatch. It costs one round and it is cheaper than a wasted review.

- **Both em-dash hooks read the working tree; neither reads the index.** So stage a file, correct it with Edit, and the commit takes the *staged* version while your check of the worktree passes. Worse, it never self-corrects: after committing, the diff shows em-dash *removal*, and the hook greps added lines only. This shipped once on 2026-08-09 and was amended out before pushing. Verify the staged blob, not the file: `git show ":$f" | grep -c` per staged path, and confirm `git diff --name-only` is empty so index and worktree agree. Ticketed as P149.

- **Gates report the instances they notice; they do not enumerate.** On 2026-08-24 one defect class fired nine times inside a single newsletter edition, three more inside the ticket documenting it, and once in a ticket about something else: a claim corrected at the site a reviewer pointed at, left standing at its siblings. Six of those were introduced BY a fix. Every gate that caught one caught an instance. The proof is occurrence four, where the skeptic condemned a phrase at one site and explicitly cleared a sibling four lines below it in the same pass. A grep sweep afterwards found that sibling, then missed a fifth in the opener because the distinguishing word was the publication's own name and the real hit drowned in the masthead. What actually closes the class is an enumeration, not a search: list every sentence whose subject is the thing and whose predicate is the claim, then check each one. Run against that edition it produced thirteen candidates, eleven real, and ended a four-round streak in one pass. The general form: **a correction has as many sites as the claim has, not as many as the person has looked at**, and the person's count of remaining sites is itself unreliable. Ticketed as P162 with nine recorded occurrences, three of them inside the ticket.

- **Your own count is not evidence, and a passing test can be false assurance about the thing you are using it to prove.** Two shapes, one session. A reported motif count of two was three on disk, because the previous round had removed one instance and added another back; an external reviewer caught it by counting. Separately, `scripts/decisions-supersession.test.mjs` passing 8 of 8 was offered as proof a decision graph was complete, when that test only verifies relationships that have been DECLARED: an undeclared `amends` is invisible to it, and there was one. Then, fixing that, an `amended-by` key was added to a record that already had one, creating a duplicate YAML key that silently dropped a relationship. The test caught that. A third shape, 2026-08-29: the source may not state the thing you are reading off it.
