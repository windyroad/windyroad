## Governance-iteration friction (2026-08-05 P120 AFK iter)

- **The compendium auto-regenerates on any `docs/decisions/*.md` edit, and re-adds em-dashes each time.** This is P087 at work, but the operational shape matters: a hook rewrites `docs/decisions/README.md` in the index after EVERY ADR edit, so stripping the em-dashes once is not enough. Three ADR edits meant three strip passes, each triggered by the `no-em-dash-bash.sh` hook firing on the next unrelated Bash call. The prior briefing entry says to revert the compendium rather than fight it; that conflicts with the architect making a regenerated compendium a confirmation criterion. What actually works: let it regenerate, strip the em-dashes as the LAST edit before staging, and expect to repeat if you touch another ADR afterwards. Batch all ADR edits first, then strip once.
- **The regenerating hook only refreshes changed entries; the header totals go stale.** After adding ADR-043 the compendium still read `**Total ADRs:** 41 (37 in-force, 4 historical)` against 43 files / 39 in-force. Check the two count lines (line 14 and the `_N ADRs._` line under In-force decisions) by hand whenever an ADR is added or a status changes.
- **The architect and JTBD edit-gates need the verdict in a specific literal shape, and a correct PASS in the wrong shape does not unlock edits.** `architect-mark-reviewed.sh` anchors on `**Architecture Review: PASS**` (bold, line-start). An agent that writes `## Architecture Review: PASS` as a heading produces an unparseable verdict, and the 0.20.2 hook fails closed on unparseable, so no marker lands and the next Write is still denied. If a review clearly passed but edits stay blocked, check the verdict's formatting before re-litigating the content. Asking the agent for the pinned shape explicitly is the fix.
- **`SendMessage` to resume a review agent does not fire the PostToolUse marker hook.** Continuing an existing architect/JTBD agent via SendMessage gets you the review, but not the gate marker; only a fresh `Agent` tool call writes it. Budget for one extra full Agent invocation when a review needs a third pass.
- **Both governance gates converge in about three passes on a change that amends ratified decisions, and the third pass is usually formatting or scope-restatement rather than substance.** Plan the iteration around it instead of treating the second ISSUES FOUND as a failure.
- **The commit gate can sit permanently at exactly the appetite boundary, and that is a policy artefact, not a scoring failure.** `RISK-POLICY.md` bands place 5 at Medium against a `< 5` appetite, so any residual of impact 5 x likelihood 1 is unreachable no matter how many controls are added. On a change touching the newsletter body (impact 5 by the policy's own table) that shape is common. The scorer will correctly refuse to soften the number; the honest routes are the `RISK_BYPASS: reducing` token when the change is net-reducing against a realised standing risk, or fixing the band. Upstream ADR-086 places 5 at Low for exactly this reason.
- **Risk-scorer remediations are worth applying even when they look like doc-nitpicks.** Two of this iteration's four applicable remediations were real defects the three review agents had missed: an ADR consequence that contradicted its own SKILL's normative table, and an unbounded re-entry cycle. Both came from the scorer, not the architect.
- **A risk-scorer finding can be wrong in a way worth pushing back on.** It claimed retired JTBD files carried no on-disk retirement signal; frontmatter said otherwise. Challenging it cost one round and it withdrew the remediation. Treat scorer claims the way P082 says to treat any subagent claim.
