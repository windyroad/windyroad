## What Will Surprise You

> Older entries rotated to [`what-will-surprise-you-archive.md`](what-will-surprise-you-archive.md) on 2026-08-08, three times on 2026-08-09, and again on 2026-08-23 (Tier 3 budget). The 2026-08-23 passes moved the commit-message external-comms gate entry, the CI smoke-test entry and the subagent-absence-claim entry, and added two from the P141 iteration and one from the P140 iteration. Rotation here is by signal rather than age, and the archive tail is deliberately NOT split further even though it is past the 2x must-split ratio: nothing loads an archive at session start, so another generation behind the `-archive-early` siblings would be churn. - **Every governance marker in this stack is written by a `PostToolUse` hook whose matcher is the literal string `Agent`, so anything that is not a fresh synchronous `Agent` spawn marks nothing.** Six hooks, one shape: architect, jtbd, risk-score, voice-tone, external-comms and style-guide. A `SendMessage` resume fires none of them, and neither does a background-launched reviewer. Only `wr-architect` documents this, in one deny string (`hooks/lib/architect-gate.sh:64`, the P400 note); the external-comms gate documents the background half only (`external-comms-gate.sh:413`, P402). The other four say nothing, so the block arrives with no way to work out why. Two corollaries worth holding. Widening the matcher would not fix it as the hooks are written, because they identify the reviewer from `tool_input.subagent_type` and a `SendMessage` payload has no such field. And on `wr-architect` 0.20.0, which is what this repo runs, verdict FORMATTING is not a cause: the mark hook routes an unparseable verdict into the same allow-with-marker branch as PASS, so a block after a genuine PASS means the marker landed under a session ID nobody reads (P088), not that the heading was the wrong shape. Recorded on P124. **The uniformity is version-pinned and is already breaking upstream**: `wr-risk-scorer` 0.18.6, sitting in the cache for another project, has collapsed its four hooks into one dispatcher whose `PostToolUse` matcher is `Agent|Bash|Edit|Skill|Write|` plus eleven agent-lifecycle events (`spawn_agent`, `wait_agent`, `close_agent` and their `multi_agent_v1__` forms). Two things follow. Re-read the hooks after any plugin upgrade rather than trusting this entry. And there is upstream precedent for widening the matcher, which strengthens the P124 fix recommendation, though note that even 0.18.6's list does not include `SendMessage`, so the resume gap plausibly survives it.

- **Two reviewers converging independently is the strongest signal this stack produces, and it means stop, not iterate.** On 2026-08-23 the architect and the JTBD reviewer, given different prompts and reading different corpora, independently killed the same drafted `.github/dependabot.yml`: the architect on the ground that it reinstated a bot authoring path whose acceptance died with a supersession, the JTBD reviewer on the ground that it routed a code-quality judgement to a persona whose file explicitly excludes it. Neither had seen the other's verdict. When that happens the answer is not a better version of the artefact, it is that the artefact is the wrong shape. Dropping it and recording the open question took one round; arguing with either reviewer alone would have taken several and landed the same place. Third observation of this pattern, after the 2026-08-09 P109 iteration and the 2026-08-23 P141 iteration. **A fourth on 2026-08-23 extends it to three reviewers and to a case where the artefact was right and one line of it was wrong**: on the P154 fix the architect, the JTBD reviewer and the voice reviewer each independently found that a new lint check stripped every parenthesised span while its own header claimed it stripped only link URLs. None had seen the others. So convergence does not always mean stop; it means the finding is real and the only question left is which surface moves. There the code moved to match the header, because the header was describing the behaviour anyone would want.

- **A fix can ship the exact defect it was written to catch, in a file the new check cannot see.** The P154 change added a lint check for two prose lines with no blank line between them, which render as one joined paragraph. The prose it added to `.claude/skills/wr-newsletter/SKILL.md` did precisely that: the paragraph carrying the load-bearing ordering rule ran on from the paragraph above it, so the bolded lead-in that was supposed to open a new instruction landed as a tail on the previous one. The check is scoped to newsletter brief bodies and could never have fired on a skill file. Two reviewers caught it by reading. The general shape is worth holding: a check you just wrote is the thing you are least likely to apply to your own output, because you are thinking of it as a thing you built rather than a rule you are under.
