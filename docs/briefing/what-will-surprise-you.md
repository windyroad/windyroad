## What Will Surprise You

> Older entries rotated to [`what-will-surprise-you-archive.md`](what-will-surprise-you-archive.md) on 2026-08-08 (Tier 3 budget).

- **A plain `mv` onto an existing directory does not refuse, and a scoped `git add -A` after a move aborts on a never-tracked source.** Both surfaced fixing P118 and both exit in ways that read like success or like an ordinary error. `mv a/<date>/ b/<date>/` where `b/<date>/` exists nests to `b/<date>/<date>/` and exits 0, so a publish step reports success while the edition falls out of the one-level-deep edition-count glob. And `git add -A <src> <dst>` after the move exits 128 with `fatal: pathspec ... did not match any files` when the source was never tracked, because the pathspec matches nothing in worktree or index; both pathspecs share one invocation, so the whole command fails after `mv` already landed, leaving the edition promoted with nothing staged. Staging the source BEFORE the move fixes it. The general lesson: reach for `test ! -e <dest>` before any scripted directory move, and reproduce each branch in a scratch repo rather than reasoning about git's pathspec rules.

- **A gate can be wired, ratified and still never have run.** ADR-044's shape gate was fully wired at two steps with a live agent file, and P121 was still open because nobody had checked whether the subagent covered the probes the ticket specified. A dry run against the published corpus settled it in one call: two of three probes fine, one real gap. Wired is not verified. Sibling shape on the P117 close: the cross-edition dropped-thread scan HAD run on Issue 16 and returned clean, on an edition that demonstrably dropped a thread. A gate that ran and reported nothing is weaker evidence than it looks.

- **"No external reviewer raised it" is not the same evidence as "the gate caught it".** Closing P117 rested on three classes: one where the gate visibly fired (verified), one where the gate visibly missed (routed to P121), and one where six rounds of external review simply produced no finding in that class. The third closes as un-contradicted, not as demonstrated, and the ticket says so. Absence of a catch is the weakest of the three and should never be written up as if it were the first.

- **A trailing-median threshold ratchets.** The post-length ceiling takes 1.5x the median of the last two editions, so one long edition raises the next edition's allowance. Issue 16 at 2,343 characters lifted the following ceiling from 2,182 to 2,986, within a whisker of the platform limit. The check catches the FIRST long edition in a run and is weakest immediately after one.

- **Sourcing a repo script to probe one helper RUNS THE WHOLE SCRIPT unless you set its LIB_ONLY variable.** On 2026-08-08 a one-line probe that did `source scripts/push-watch.sh` (to reach a pure helper) executed the real push flow: stash, `pull --rebase`, `dry-aged-deps --update --yes`, CI check, and `git push`. Four already-committed commits went to origin/master in an iteration explicitly told not to push. The seam is opt-IN, not opt-out: `PUSH_WATCH_LIB_ONLY=1` / `FIX_DEPS_LIB_ONLY=1` must be exported BEFORE the source, exactly as `scripts/*.test.mjs` does it, and the safe shape is a subshell (`bash -c 'export X_LIB_ONLY=1; source ...'`) so a forgotten export cannot leak into the rest of the session. Reading the helper's source, or calling it from the existing test harness, is safer than sourcing the script at all.

- **The architect can take five rounds, and the later rounds are the valuable ones.** The P126 fix went ISSUES FOUND four times before PASS. Round 1 caught two ADRs cited for things they do not say (ADR-052 does not exist in this repo; ADR-014 is Wardley mapping, not commit grain). Round 3 caught that the design had grown three new behavioural contracts needing their own ADR, which would have blocked the fix behind ratification; reshaping to remove all three was cheaper than documenting them. Budget for the rounds rather than treating the first ISSUES FOUND as the whole cost, and prefer reshaping the design over documenting a new contract when a new ADR would need a human who is not there.

- **The external-comms gate cannot see a body passed with `--body-file`, and the block it emits is then unclearable.** The PreToolUse gate scrapes the draft out of the command string itself, matching a heredoc, then `--body "..."`, then `-m "..."`. With `--body-file /tmp/x.md` nothing matches, so it hashes an EMPTY draft: `sha256("" + "\n" + surface)`. The reviewer subagent hashes the real body from its `<draft>` block, the two keys never meet, and the gate re-blocks after a genuine PASS with the same message telling you to do the review you just did. Nothing in the message hints at the cause. The fix is to pass the body inline as `--body "$(cat <<'EOF' ... EOF)"`, which the gate parses first and by design. Two other traps sit next to this one: the reviewer must be dispatched SYNCHRONOUSLY (a background agent never fires its PostToolUse mark hook), and its prompt must literally start with a `SURFACE: <name>` line and wrap the body in `<draft>...</draft>` markers, or the key is never derived at all. A review run without that shape is wasted work, however good the review is. Observed 2026-08-08 filing agent-plugins#413.

- **A lint check's own failure message can teach the system how to evade it.** A never-scored message drafted on 2026-08-08 read "re-run that gate, or mark the block carried if it came from prep". The actor reading it is the agent that just edited the body, so the message offered a one-line alternative to doing the work. Read new gate messages as instructions to the party with the motive to skip.

- **Nine problem tickets carry `**JTBD**` / `**Persona**` header lines, and every populated one names an artefact this repo does not have.** P088, P096, P097 and P098 say `**Persona**: plugin-developer` with `JTBD-006` or `JTBD-007`; P124 says `developer` with `JTBD-001`. This repo has no `plugin-developer` persona and no JTBD-006 or 007, and its JTBD-001 is Awareness, an Engineering Leader consulting job retired by ADR-041 on 2026-07-10. The values are the upstream `agent-plugins` corpus leaking in, the same collision class as bare `ADR-NNN`. P125 found this for itself on 2026-08-08 and rewrote its own two lines to say so; the other five were not touched. Two consequences. A ticket's header anchoring is not evidence of anything until you have opened `docs/jtbd/` and confirmed the ID exists here. And the local convention is genuinely no header lines at all: the majority of tickets, including every one captured recently, carry Status / Reported / Priority / Origin / Effort / WSJF and record anchoring in prose under `## Related`. A capture that adds the header lines is diverging from the corpus, not conforming to it.
