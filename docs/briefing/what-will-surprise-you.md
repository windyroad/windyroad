- **The commit-message external-comms gate is a DIFFERENT trap from the `--body-file` one above, and the recipe lives in the plugin's briefing, not this repo's.** The gate parses the raw command string with a first-match-wins loop over `-m` and captures only the FIRST one, while the reviewer subagent hashes whatever you wrapped in `<draft>`. So a multi-`-m` commit reviewed as a full body produces two different keys and re-blocks after a genuine PASS, with a message telling you to run the review you just ran. Three recipes work: a single `-m` inlining the whole message reviewed as full text; a multi-`-m` commit reviewed as the SUBJECT LINE ONLY; or `git commit -F <file>`, which sidesteps the gate entirely because it arms only on `-m`/`--message`. The `-F` form is cleanest for anything multi-paragraph. Read `~/.claude/plugins/marketplaces/windyroad/docs/briefing/external-comms-commit-msg-gate.md` BEFORE composing a long commit message; it has been re-hit six-plus times and hitting it again costs a full round trip. One more variant, hit twice on 2026-08-09: even with a SINGLE heredoc `-m`, the gate hashes the message the commit actually carries, INCLUDING the `Co-Authored-By` trailer. Reviewing the body without the trailer produces a different key and the commit re-blocks after a genuine PASS. Put the whole message, trailer and all, inside `<draft>`. Ticketed as P085.

- **The external-comms gate cannot see a body passed with `--body-file`, and the block it emits is then unclearable.** The PreToolUse gate scrapes the draft out of the command string itself, matching a heredoc, then `--body "..."`, then `-m "..."`. With `--body-file /tmp/x.md` nothing matches, so it hashes an EMPTY draft: `sha256("" + "\n" + surface)`. The reviewer subagent hashes the real body from its `<draft>` block, the two keys never meet, and the gate re-blocks after a genuine PASS with the same message telling you to do the review you just did. Nothing in the message hints at the cause. The fix is to pass the body inline as `--body "$(cat <<'EOF' ... EOF)"`, which the gate parses first and by design. Two other traps sit next to this one: the reviewer must be dispatched SYNCHRONOUSLY (a background agent never fires its PostToolUse mark hook), and its prompt must literally start with a `SURFACE: <name>` line and wrap the body in `<draft>...</draft>` markers, or the key is never derived at all. A review run without that shape is wasted work, however good the review is. Observed 2026-08-08 filing agent-plugins#413.

- **A leaked cross-repo JTBD or persona citation gets WORSE over time, because the local corpus grows into the collision.** Five tickets carried `**JTBD**` / `**Persona**` header lines naming upstream `agent-plugins` values. Fixed 2026-08-09; the durable lesson is in how they failed. `plugin-developer` and `JTBD-007` never existed here, so they dangled, which is loud and harmless. `JTBD-001` and `JTBD-006` are the dangerous shape: both resolve to real local Engineering Leader reader jobs, so the citation reads as grounded while pointing somewhere unrelated. JTBD-006 was still dangling when four of these tickets were captured and only became a wrong-but-resolving citation when the job was written on 2026-08-09. A dangling reference you leave alone can silently become a confident false one. Verify a header anchoring against `docs/jtbd/` before trusting it, and note the local convention is no header lines at all: tickets carry Status / Reported / Priority / Origin / Effort / WSJF and record anchoring in prose under `## Related`. Same collision class as a bare `ADR-NNN`.

- **Every governance marker in this stack is written by a `PostToolUse` hook whose matcher is the literal string `Agent`, so anything that is not a fresh synchronous `Agent` spawn marks nothing.** Six hooks, one shape: architect, jtbd, risk-score, voice-tone, external-comms and style-guide. A `SendMessage` resume fires none of them, and neither does a background-launched reviewer. Only `wr-architect` documents this, in one deny string (`hooks/lib/architect-gate.sh:64`, the P400 note); the external-comms gate documents the background half only (`external-comms-gate.sh:413`, P402). The other four say nothing, so the block arrives with no way to work out why. Two corollaries worth holding. Widening the matcher would not fix it as the hooks are written, because they identify the reviewer from `tool_input.subagent_type` and a `SendMessage` payload has no such field. And on `wr-architect` 0.20.0, which is what this repo runs, verdict FORMATTING is not a cause: the mark hook routes an unparseable verdict into the same allow-with-marker branch as PASS, so a block after a genuine PASS means the marker landed under a session ID nobody reads (P088), not that the heading was the wrong shape. Recorded on P124. **The uniformity is version-pinned and is already breaking upstream**: `wr-risk-scorer` 0.18.6, sitting in the cache for another project, has collapsed its four hooks into one dispatcher whose `PostToolUse` matcher is `Agent|Bash|Edit|Skill|Write|` plus eleven agent-lifecycle events (`spawn_agent`, `wait_agent`, `close_agent` and their `multi_agent_v1__` forms). Two things follow. Re-read the hooks after any plugin upgrade rather than trusting this entry. And there is upstream precedent for widening the matcher, which strengthens the P124 fix recommendation, though note that even 0.18.6's list does not include `SendMessage`, so the resume gap plausibly survives it.

- **Budget three review rounds for a commit message that makes factual claims, and expect each fix to cost a full round.** On 2026-08-09 one `docs(problems)` message went through `wr-risk-scorer:external-comms` three times, and every round returned PASS while surfacing a real error in the prose: an absolute that was false ("installed nowhere" for a plugin version installed under another project), a date off by one, and an account of which values leaked that omitted one of the five tickets. The gate's PASS is about leaks and policy classes, not accuracy, so the accuracy findings arrive as advisory prose alongside a PASS you could simply act on. Reading past the verdict is where the value is. The round cost is structural: the marker key hashes the draft, so correcting a single word after a PASS invalidates it and forces a fresh dispatch. Ask the reviewer to verify claims against disk explicitly; it is one sentence in the prompt and it is what caught all three.
