- **`npm run deps:check` can be green on this machine while the identical command on the identical commit is red on CI, and `fix:deps` will then tell you there is nothing to fix.** Observed 2026-08-29/30. Installed versions matched CI exactly and `npm outdated` agreed with CI on every `latest`, so version resolution is not the difference; only the derived package age is. CI named `@types/react` and `playwright` at exactly 30 days against the 30-day dev floor and exited 1, the local run reported no matured outdated packages and exited 0. Because `scripts/fix-deps.sh` opens with `if npx --no-install dry-aged-deps --check; then ... exit 0`, the documented remedy returns before it does anything. So diagnose a red freshness step from `gh run view <id> --log-failed`, not from the local gate, and read the `Outdated packages` table rather than the long advisory table under it, which `dry-aged-deps` prints without changing its exit code. Two other things bite the same job: `npm` 12 defaults `allow-remote=none`, so resolving any package with `bundleDependencies` dies `EALLOWREMOTE` on a normal registry tarball until you pass `--allow-remote=all`; and `npm update --package-lock-only` here fails outright on a peer conflict, so target the packages by name instead. The divergence is on P183 and the peer conflict on P184; the `allow-remote` default is recorded only here.

- **The external-comms gate hashes a commit message as subject, blank line, then body, so a `<draft>` block holding only the body never matches and the gate re-blocks after a genuine PASS.** Same deny-after-PASS class as the `--body-file` case the roll-up carries, different cause, and on 2026-08-30 it cost two dispatches spent purely on the key, one adding the trailer and one adding the subject, before the hook was read rather than guessed at. `external-comms-gate.sh` collects every `-m` argument and joins them with `\n\n`; the mark hook hashes whatever sits between `<draft>` and `</draft>`. Anything that lands in the real command must be in the block, the `Co-Authored-By` trailer included, or the keys differ. Two consequences worth holding: any later edit to the message invalidates the marker and needs a fresh synchronous review, so settle the wording before the first dispatch; and the commit-risk gate is separate and fires first, with its own subagent. The evaluator that blocks here is `wr-risk-scorer:external-comms`, not the voice one: both plugins ship a byte-identical `external-comms-gate.sh`, but `wr-voice-tone`'s `external-comms-evaluator.conf` sets `EXTERNAL_COMMS_SKIP_SURFACES=git-commit-message` and the risk one leaves it empty, so only risk ever denies a commit. Read the extraction in `~/.claude/plugins/cache/windyroad/wr-risk-scorer/<highest>/hooks/external-comms-gate.sh` rather than guessing at it, since the shape differs per surface.
