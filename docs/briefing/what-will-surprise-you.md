- **Resolving a governance reviewer's findings by `SendMessage` is the right review move and the wrong marker move, and the roll-up's "dispatch a fresh synchronous Agent spawn" does not read as a warning about it.** The Critical Points entry on the six gates is correct and was in context on 2026-08-29 during the P099 iteration; the trap was still walked into, which is what makes this worth its own entry. The pull is real: when the architect returns ISSUES FOUND, resuming that agent is genuinely better review practice, because it keeps the context that produced the findings and lets the reviewer check that the resolution actually answers them. Both the architect and the JTBD reviewer were resumed that way, both upgraded to PASS on the merits, and both edits stayed blocked, because a `PostToolUse` hook matching the literal string `Agent` never fired. Recovery cost two full re-spawns of reviews already passed. The shape that gets both things: iterate by `SendMessage` as much as you like, then make the FINAL pass a fresh synchronous `Agent` call carrying the settled design. That final spawn is not wasted ceremony, since it re-reads the artefact from disk and is the one that writes the marker. Only `wr-architect` names the trap, in its deny string, and the JTBD gate is the one likelier to be hit first because its scope is every project file. Fourth recorded witness; the mechanism and the other three are on P124.

- **A story map's `<meta name="problems">` is derived from the story corpus, so hand-setting it is undone by the very render you are told to run afterwards.** On 2026-08-30 a JTBD review of the two new story maps found that neither carried a problem trace, and asked for `content="P099"` and `content="P126"` to be written in and the maps re-rendered so the problem-side reverse tracer would pick them up. The problem ids were right; the fix was not. `renderMeta` in the upstream renderer writes `(derived.mapProblems ?? []).join(',')` with no authored-value alternation, deliberately, so that a stale island cannot outvote the corpus, and `mapProblems` is the union of each card's story's `problems:` frontmatter. Both maps' cards carry a bare `ref` and no `storyId`, and `docs/stories/` does not exist, so the union is empty by construction. Setting the tag and re-rendering reverts it to empty in the same breath, which is what happened when it was tried. The tag only becomes writable by standing up the story tier, and that is not a bigger version of the same edit: the renderer's `assertEveryCardHasAStory` check returns early only while the stories directory is absent, so creating it breaks rendering of both maps until each card gains a story, and it forces the legacy-RFC question ADR-058 leaves open for ratification. The general shape is worth more than the instance. Several `<meta>` tags on a rendered map look authored and are not, and the renderer is the only place that says which is which; check there before hand-editing one, and treat a reviewer's proposed edit to a generated file as a hypothesis about that file's provenance.
